Amazon JP Launch OS · 当前架构复审

下图和原始审查证据保留修复前快照；修复结果及剩余人工验证边界见页面末尾。

P0 · 控制与来源

Gate 顺序受控，但通过依据可由调用方自填；没有 G0–G12 与各校验器输出的强绑定。

Report Manifest 仅按报告类型索引，放量决策没有确认报表覆盖当前 SKU。

P0 · 广告预算

活动预算设置了每组至少 300 JPY 的下限。500 JPY 总预算可生成 600 JPY 的两个活动预算。

目标行重复写入活动预算，CSV 还缺明确的 campaign 与 target 分表。

P1 · 完整性与证据

零退货或零评论的表头-only 报表被拒绝，导致新 SKU 无法形成完整 Manifest。

人工 proof 目前只检查非空文件；同一文件可用于多个不同字段。真实 SKU 链路尚未验收。

审查证据与修复顺序

P0 · Gate 来源未验证。 record_gate.py:72-79 只核对 CSV 的 sku/gate/decision 字段和证据文件存在性，未校验决策由对应阶段的校验器生成，也未核对输入哈希。复现：用自填的 13 份 pass CSV 和同一个任意文本文件依次记录 G0–G12，状态变为 complete。应为每个 Gate 固定校验器、输入清单和决策产物，并在推进时验证产物来源与摘要。

P0 · 广告预算可超支。 plan_amazon_ads.py:155-156,175-195,257-268 每个活动独立取至少 300 JPY。复现：SKU 日预算 500 JPY，Auto 和 Exact 活动各分到 300 JPY，合计 600 JPY。应先检查活动数与最小预算的可行性，再按活动分配且保证总额不超过 SKU 预算。

P0 · 报表不能证明 SKU 覆盖。 normalize_live_reports.py:250-255 的 manifest 没有 SKU/ASIN 范围；review_performance.py:219-240,276-308 只按报告类型检查，且仅检查哈希长度、文件存在。复现：五份只含 SKU-A 的报表清单也得到空问题列表，可支持 SKU-B 的 scale 指标行。应把报表的 SKU 范围、期间、行数和真实 SHA-256 与决策行逐一绑定。

P1 · 零事件与人工证据。 normalize_live_reports.py:189-190 拒绝只有表头的退货或评论报表；review_performance.py:236-239 也拒绝零行。build_seller_central_checklist.py:93-107 和 plan_fba_shipment.py:97-101 只检查 proof 文件非空，未验证内容、SKU 或操作时间。应为零事件引入有来源的明确声明，并给 proof 增加字段级关联与人工复核。

P1 · 状态写入一致性。 record_gate.py:84-98 顺序追加两个 CSV 后才替换 JSON，没有锁或跨文件事务；中途失败或并发调用会留下互相矛盾的记录。应使用单一事务存储，或实现锁、预写日志和恢复校验。

验证范围。 运行 PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v：17/17 通过；另用临时目录复现上述三个 P0 场景。工程尚无真实 SKU 从原始导出到后台证明及复盘的验收记录。

修复结果 · 2026-11-12

G6 由记录器重新运行 Launch Gate 校验器，伪造的 pass CSV 无法单独推进；状态 JSON 在工作区锁内提交，CSV 从该状态重建。

广告预算按活动统一分配，低于 600 JPY 时只保留 Auto；campaigns.csv 与 targets.csv 分离，预算只出现在活动行。

Report Manifest 增加 SKU 范围与规范化文件 SHA-256；复盘逐 SKU 检查范围、业务/库存行、源文件和规范化文件摘要及行数。零行退货/评论报表需显式 SKU 范围。

Launch Gate 的 pass 证据必须是本地非空快照；Seller Central 与 FBA proof 拒绝空文件、非支持格式和同一文件复用多个字段。回归测试 24/24 通过。

仍需人工验收：

外部 URL 或截图的真实内容、导出范围是否与 Seller Central 一致，以及真实 SKU 的完整运行，无法仅靠本地 CSV 校验确认。G0–G5、G7–G12 的人工 Gate 决策仍依赖审批人审查，不能视为自动验证。
